SHARED FAIL-FAST LOCK PROTOCOL v1

This file is an authoritative extension of Validator v10.2 section 4 only when
validator/runtime_lock_v1.enabled exists on main.

Paths:
- gate: validator/runtime_lock_v1.enabled
- lock: validator/runtime.lock

Validator protocol:
1. Before PATCH_ROOT inspection or batch scanning, generate a unique opaque LOCK_TOKEN.
2. Acquire the lock only with GitHub CREATE-file at validator/runtime.lock on main.
3. The lock JSON must contain exactly:
   {"schema_version":1,"owner":"validator","token":"<LOCK_TOKEN>","acquired_at":"<UTC ISO-8601>"}
4. If CREATE reports that the lock already exists, stop unchanged immediately.
   Do not wait, retry, update, replace, delete, or take over the existing lock.
5. Any other acquire failure is a systemic repository failure.
6. While the lock is held, before every patch CREATE, reread validator/runtime.lock and
   require schema_version=1, owner="validator", and token=LOCK_TOKEN.
   On mismatch/missing/unreadable lock, do not create the patch and stop.
7. After successful acquisition, every normal exit and every handled-failure exit must
   release in final cleanup after patch work has finished or stopped:
   reread the lock, obtain its current blob SHA, verify the same owner/token, and DELETE
   exactly validator/runtime.lock using that SHA.
8. Never delete a missing, foreign, replaced, or ownership-mismatched lock.
9. There is no stale timeout, automatic takeover, wait loop, or retry loop.
10. CREATE/DELETE of validator/runtime.lock are explicitly permitted exceptions to the
    later patch-only repository-persistence restrictions in section 4. No other exception
    is introduced.
